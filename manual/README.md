# NTFS Search 使用说明

## 启动

把 Windows x64 便携包解压到 Windows 本地的可写目录，双击「启动搜索.cmd」，或打开顶层的 `NtfsSearch.App.exe`。各版本均使用系统的 WebView2 Runtime。

| 包名后缀 | 查询服务 | .NET 运行时 |
| --- | --- | --- |
| `framework-dependent` | HTTP 和实时 CLI | 系统需安装 x64 的 .NET Runtime 10 和 ASP.NET Core Runtime 10 |
| `self-contained` | HTTP 和实时 CLI | 随包提供 |
| `self-contained-no-http` | 桌面搜索与 CLI 静态诊断 | 随包提供基础 .NET |

程序会自动发现本机已就绪的 NTFS 磁盘。Windows 可能显示 UAC 授权提示，确认后才能采集磁盘和持续监控。一个卷建立或加载索引后即可搜索该卷。

## 搜索文件和文件夹

- 打开窗口即可输入。默认匹配完整路径，从顶部「搜索」菜单可切换到「仅匹配名称」。按 `Ctrl+F` 回到搜索框。
- 点搜索框旁的「全部」可以多选「文件夹」「文件」。默认全选，修改后会筛选整个结果集。「空间分析」可直接打开分析页，点「返回搜索」回到原搜索。
- 从顶部「搜索 → 高级搜索」可设置创建日期、修改日期、文件大小和后缀。点「应用」后与关键词和类型选项一起筛选，底栏显示已应用的高级条件数量。「清除条件」后点「应用」可恢复普通搜索。
- 日期按本地时间筛选，包含起止两天。文件大小以字节为单位，上下限均包含。后缀选项按 Windows Shell 规则从已发布索引动态生成，可以查找、多选或选「无后缀」。最后一个点后含普通空格的名称和 Go 模块校验缓存中的版本记录归入「无后缀」。未关联应用的后缀也可筛选。取消所有后缀选择表示任意后缀。后缀只筛选文件，文件夹由类型选项控制。
- 输入 `hello world` 匹配同时包含两条条件的结果，名称和完整路径中命中的 `hello`、`world` 各自加粗。输入 `"hello world"` 匹配并加粗包含空格的连续短语。「仅名称」模式下，普通条件在名称列及完整路径末尾的名称部分加粗。
- 搜索路径时可以用 `/`、`\` 或两者混用。例如 `"D:/Project Files/report.txt"` 与 `"D:\Project Files\report.txt"` 等价，结果显示原始 Windows 路径。桌面、HTTP 和 CLI 都使用这套路径匹配规则。
- 点击名称、完整路径、大小或修改时间的列标题排序，再点一次切换方向。拖动列标题右边缘可调整宽度。表格超出窗口时，可用横向滚动条或在结果区按住 `Shift` 滚轮左右查看。文件大小自动切换单位，悬停可查看精确字节数。底栏显示匹配总数和当前页，可逐页查看。
- 文件使用 Windows 对应类型的图标，目录使用目录图标。
- 大小列显示目录中已索引文件的逻辑大小合计，硬链接按路径计入。空目录显示 `0 B`。后台计算期间可以继续搜索，当前页会自动补齐大小。按大小排序时文件与目录一起排序，待计算的目录会在统计就绪后自动重新排序。含未知大小文件的目录显示 `—`。
- 在「设置」中可以关闭「计算搜索结果中的文件夹大小」并保存，释放搜索占用的目录统计内存。空间分析仍可按需计算。
- 在搜索框按向下键进入结果表。双击结果或按 `Enter` 打开选中项。右键选择「打开所在目录」会在资源管理器中打开父目录并选中该项。条目已移动或删除时，窗口会显示错误提示。右键菜单或 `Ctrl+C` 可复制完整路径。
- 结果表支持 `Ctrl`+单击切换选中、`Shift`+单击选择范围、`Ctrl+A` 选中当前页。从空白处或名称以外的列按住左键拖动可以框选，拖到列表上下边缘时会自动滚动。按 `Esc` 可取消这次框选。
- 从文件名或图标按住左键拖出，可将所选文件交给浏览器的上传区或其他应用。拖到资源管理器时，按系统的放置提示确认该操作是复制还是移动。

## 界面语言

打开「设置 → 通用 → 语言」，可选择「跟随系统」、简体中文或 English。默认使用 Windows 显示语言，找不到对应的译文时使用英文。点击「保存并应用」后，当前窗口和托盘菜单会切换到所选语言。

## 调整索引内存占用

从「工具 → 设置」打开「索引」并保存。**预计算排序立即生效**。创建时间、修改时间和文件大小在**下次完全退出并重新启动**后生效。关窗到托盘会保持本次启动的元数据设置。

| 设置 | 默认 | 关闭后 |
| --- | --- | --- |
| 预计算排序 | 开启 | 首次使用一列时才计算，桌面只保留当前列的排列。切到其他列时可能需要等待，同列切换升降序和翻页可以复用排列。 |
| 索引创建时间 | 关闭 | 桌面、HTTP 和 CLI 的创建时间筛选停用，HTTP 和 CLI 返回的 `createdUtc` 为 `null`。 |
| 索引修改时间 | 开启 | 隐藏修改时间列，停用修改时间排序和筛选，返回的 `modifiedUtc` 为 `null`。 |
| 索引文件大小 | 开启 | 隐藏大小列，停用大小排序和筛选、搜索结果的文件夹大小统计和空间分析，返回的 `sizeBytes` 为 `null`。 |

重新开启预计算排序后，程序用已有索引在后台补建。期间可以继续查询。关闭时保留当前列，其他排列在正在执行的查询用完后释放。

重新启用文件大小后，搜索结果的文件夹大小统计按已保存的偏好恢复。重新启用某个元数据字段时，已有该字段的快照可以直接恢复。缺少该字段的卷会提示并重新采集。

## 通过 HTTP 和 CLI 查询

本节适用于普通版和自包含完整版。

桌面程序默认在 `http://127.0.0.1:18791` 提供本机 HTTP/JSON 接口。关窗进入托盘期间，接口继续使用实时索引。

从主窗口或托盘右键菜单打开「设置」。设置分为「通用」「搜索」「索引」「空间分析」「搜索服务」。切换标签页时保留未保存的编辑，底部的「保存并应用」一次保存所有标签页的修改。

在「搜索服务」可以启停 HTTP 搜索服务、修改端口并查看实际访问地址。无 HTTP 服务版隐藏这个标签页。「重启服务」使用已保存的配置重启 HTTP 监听，索引和桌面搜索继续运行。CLI 自动读取同一便携目录中的端口设置。使用环境变量 `NTFS_SEARCH_PORT` 时，它会覆盖已保存的端口。

设置页可复制一行 Linux 或 WSL 命令，按实际端口查询 Windows 自带的文件。以默认地址为例。

```sh
curl -sS --json '{"text":"C:\\Windows\\explorer.exe","limit":1}' http://127.0.0.1:18791/v1/search
```

WSL 2 镜像网络支持通过 `127.0.0.1` 访问这个接口。使用 NAT 网络时，可通过 WSL 互操作运行 Windows 版 CLI。 [Microsoft WSL 网络说明](https://learn.microsoft.com/zh-cn/windows/wsl/networking)

- `GET /v1/status` 返回已索引条目数 `indexed`、可查询卷数 `volumesReady` 和各卷状态 `volumes`。
- `POST /v1/search` 接收 JSON。可传 `text`、`matchPath`、`sort`、`descending`、`offset` 和 `limit`。排序字段使用 `name`、`path`、`size` 或 `modified`。省略查询文本即可只按元数据筛选。
- 搜索响应包含精确总数 `total`、可查询卷数 `volumesReady` 和当前页 `rows`。默认返回 100 条，最多 1000 条。`limit: 0` 只统计数量。`volumesReady` 为零表示暂时没有已就绪的卷。
- 某个排序列尚未备好时，首次查询可能耗时较长，本机搜索服务允许该请求最长运行 60 秒。
- 搜索行包含 `name`、`fullPath`、`isDirectory`、`sizeBytes`、`createdUtc` 和 `modifiedUtc`。需要无损还原特殊 NTFS 路径时，可将 `pathKey` 按 Base64 解码为原始 UTF-16LE 路径。
- 日期筛选使用带 `Z` 或 `±HH:mm` 时区的 ISO 8601 时间，秒的小数最多 7 位。起点包含，终点排除。大小以文件逻辑字节数计算，上下限均包含。组合条件同时成立才命中。缺少所筛选元数据的条目会被排除。

例如，搜索 2026 年 11 月起创建和修改、大小至少为 100 MiB 的报告文件，可向 `POST /v1/search` 发送以下请求。请先在「设置 → 索引」开启「索引创建时间」，保存并重启。请求中显式使用已关闭的字段进行排序或筛选时，HTTP 会返回 400 和对应说明，CLI 会报错。

```json
{
  "text": "report",
  "createdFrom": "2026-11-01T00:00:00Z",
  "modifiedFrom": "2026-11-01T00:00:00Z",
  "minSizeBytes": 104857600,
  "sort": "modified",
  "descending": true,
  "limit": 20
}
```

便携包中的 CLI 可发送同样的查询，并输出 JSON。

```powershell
.\NtfsSearch.Cli.exe status
.\NtfsSearch.Cli.exe search report --created-from 2026-11-01T00:00:00Z --modified-from 2026-11-01T00:00:00Z --min-size-bytes 104857600 --sort modified --descending --limit 20
```

使用 `--created-before`、`--modified-before` 或 `--max-size-bytes` 设置上限。后端不可用时，CLI 报错并返回非零退出码。开发诊断可用 `search-snapshot` 查询指定的静态 `.ntidx`。

## 查看空间分析

启用「索引文件大小」后，点击搜索框右侧的「空间分析」，选择已有索引的磁盘。矩形面积随逻辑大小变化。默认显示两层，空间足够的文件夹会自动显示子项。可用「细节」或 `Ctrl` 加加号、减号调整层级。

磁盘下拉框默认在盘符右侧显示已用空间、总容量和百分比，行背景按该比例填色。容量来自 Windows，进入空间分析或展开列表时刷新。在「设置 → 空间分析」可切换为剩余空间、关闭背景用量条，或关闭整个容量显示。点击「保存并应用」后立即生效。

单击任意层的文件夹可就地展开，继续单击子目录可逐层展开。切到其他分支会收起上一条分支的临时展开，保留共同上级。空间不足时可双击文件夹，或聚焦后按 `Enter` 放大目录，点击面包屑返回上级。矩形上的大小后显示占当前目录的比例。矩形、底栏和悬停提示均使用自适应大小单位。点击文件在资源管理器中定位。

文件变化时，树图会短暂高亮该文件所在分支中最深的可见文件夹。子目录未显示时，高亮最近的可见上级。多个分支有变化时，各自高亮对应文件夹，同一个文件夹每批只高亮一次。

右键文件或文件夹可使用搜索结果中的「打开」「打开所在目录」和「复制完整路径」。「打开所在目录」会在资源管理器中选中该项。文件还可用「打开方式…」选择应用，未关联应用的文件也会在打开时提示选择。

右键选择「临时排除」可从树图中移除文件或整个文件夹，并扣除其在各级父目录中的大小。点击「已排除 N 项」可逐项或全部恢复。切换目录、磁盘或返回搜索时，排除项在本次运行期间保留。

在地址栏可粘贴已索引的本地目录路径，例如 `D:\Games\SteamLibrary`，按 `Enter` 或点击「打开」。输入 `D:` 可直接查看卷根。输入跨卷目录会自动切换磁盘。目录无法定位时，提示会出现在地址栏下方，当前树图可继续使用。

目录大小是其中已索引文件逻辑大小的合计，硬链接按路径分别计入。小条目可合并为「其他」，其大小仍计入合计。打开空间分析或切换磁盘时，程序用已有索引汇总选中卷。后台索引更新后树图会一起刷新。

「返回搜索」保留原搜索位置。再次打开空间分析时，继续查看上次的磁盘、目录和展开分支，保留细节层级及未提交的地址，并按最新索引刷新。窗口重新进入前台时，正在查看的空间分析仍保持打开。

## 查看和处理索引状态

底栏的「索引状态」显示已索引数量、各卷进度和错误原因。可在此重新扫描磁盘或取消采集。取消采集后仍可搜索已经加载的索引。

启动时，每个卷会分别显示快照检查、读取、重建排序和 USN 补读阶段。实时监控状态会说明本次从快照恢复或经过全卷采集。只有无可用快照、USN 失效需要重建或手动重扫等情况才进行全卷采集。

## 退出和移动

点击窗口关闭按钮或按 `Alt+F4` 会隐藏窗口，索引和查询继续运行。左键点击托盘图标或右键选择「打开」可恢复窗口。从托盘打开、用 `Alt+Tab` 切回或通过任务栏恢复时，可以直接在搜索框输入。切回搜索页时保留现有搜索词、结果选中项和未保存的设置草稿。右键选择「退出」时，程序停止查询与采集并显示索引保存进度。各卷索引完整后，程序分卷压缩文件元数据，并写入程序同目录的 `index.ntsnap`。下次启动时逐卷恢复，按设置建立排序，并补读停机期间发生的变化。

在退出保存界面可以点击「此次不保存」。程序会结束本次临时写入、清理临时文件并退出，上次完整的索引快照可在下次启动时使用。进入最终替换阶段后，界面显示「正在完成保存」，本次会正常保存。按钮只作用于本次退出。

在「设置」中可切换「退出时保存索引」，通过底部按钮保存。也可在「索引状态」直接切换「退出时不保存索引」，即时保存。两个入口控制同一个退出偏好，记在程序同目录的 `settings.json`。关闭退出保存时，程序保留上次保存的快照。

升级旧版时，先从托盘退出程序，再手动将旧 `Data/` 中的 `index.ntsnap` 和 `settings.json` 移到新版程序同目录。新版从顶层读取这两个文件。移动便携版时可一起带走它们。保存快照需要程序目录可写。
