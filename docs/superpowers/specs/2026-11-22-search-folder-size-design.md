# 搜索结果的目录大小与排序

## 桌面搜索行为

桌面搜索的「大小」列显示目录内所有已索引后代文件的逻辑大小，与空间分析使用同一个统计口径。硬链接按路径计入，目录合计涵盖整个已索引子树，即使其中的文件未命中当前搜索。空目录显示 `0 B`。大小尚在汇总或有后代文件大小未知时显示 `—`，悬停提示相应原因。空间分析中的临时排除只用于树图。HTTP、CLI 和静态快照查询沿用现有契约，大小范围仍筛选文件。

索引卷发布后立即可搜索。按名称、路径、修改时间排序时，先返回当前页和精确总数。目录合计可用后，只更新当前页相关行的大小，保留原有行序、页码、选中项、滚动位置和用户查询耗时。补值与当前请求及卷视图绑定，迟到的结果丢弃。每页仍至多构造 200 行。

按大小排序时，文件与大小已知的目录按同一逻辑字节值排序。已知值相同时沿用现有路径及稳定的决胜规则。无论升序或降序，未知值均排在已知值之后。大小排序在分页前完成。

查询涉及的卷若仍在汇总，大小排序先使用与该次查询视图对应的已知值，其余目录暂按未知值处理。返回最新索引中的精确计数和当前页，并标明「正在计算目录大小，排序待更新」。当对应的统计和顺序就绪后合并刷新，按当前查询完整归并。后代文件大小缺失的目录在汇总后仍按未知值处理。统计失败时，桌面显示失败状态，已有搜索结果仍可使用。

## 后台汇总与排序

复用空间分析按完整 NTFS 文件引用关联父子目录、自底向上汇总、比较新旧索引视图和应用增量的逻辑。空间分析为显示子文件维护的行号排列按需构建。搜索只需保存目录合计、未知计数与目录排序所需的数据。卷在可搜索后单独排队汇总，每次只处理一个卷。普通查询既不等待这个任务，也不为每条命中或每棵目录子树重新汇总。用户发起查询时，后台任务在分段检查点暂停并保留进度，查询返回后恢复。统计结构按卷释放，旧任务的结果不得跨卷或索引代次应用。

文件新增、删除或改大小时，按批更新直接父目录和祖先。目录移动时，把子树合计从旧祖先链转到新祖先链。卷视图被替换或索引合并后无法沿用差异时，在后台为新的卷视图重建。增量任务合并同卷更新，普通查询可继续读取已发布索引。汇总、排序和结果取值使用同一卷视图，查询期间固定所用视图，避免使用旧行号或旧大小参与新视图排序。普通搜索因汇总就绪而补值时，复用已经返回的结果页。大小排序的后台刷新沿用桌面现有合并机制。

沿用原有文件大小排列，另维护已知大小目录的有序行号。寻找匹配仍复用现有逻辑和匹配位图。宽查询用有序流归并文件、目录和各卷，在归并完成分页后才构造返回行。少量命中可以复用现有稀疏排序路径及同一比较规则。增量批次按新增、删除、行身份变化和大小变化更新目录顺序，控制更新时的临时占用。每次输入或翻页均复用已经发布的统计和顺序。

目录统计是从实时内存索引派生的数据。首次汇总读取已发布的索引，沿用现有退出快照，并支持从旧快照恢复后在后台计算。桌面退出、卷卸载或旧代次淘汰时取消不再需要的任务和结果。

## 方案取舍

按命中逐个遍历磁盘目录会使开销随结果数和子树体积增长，父子目录同时命中时还会重复遍历。把合计直接写回所有目录行并在每次变化后重建全卷大小排列，会把目录变化的成本叠加到文件排序和索引发布上。按卷汇总加独立的目录顺序，把冷建成本移到后台，并保留普通搜索和已有文件排序的快速路径。

现有九卷约 3484 万条记录的空间分析实测中，单卷首次汇总加读取耗时 18.2 至 1023.1 ms，额外保留 23.0 至 415.1 MiB。该版本还包含树图相关的行号索引，这组数字用于对照，搜索用汇总和排序的资源开销需要单独测量。 [空间分析基准](../../benchmarks/space-analysis-0.8.0/README.md)

## 验收

- 用受控数据比较搜索与空间分析的目录合计，覆盖硬链接、深层目录、空目录、未知大小及大文件。验证新增、删除、大小变化、文件移动、目录整体移动、卷卸载和索引合并。
- 对照完整排序后的结果验证大小升降序、同大小、未知值、多卷归并和跨页边界。分别覆盖高密度匹配和稀疏匹配。验证冷启动暂排状态、就绪后的自动刷新、旧请求作废，以及普通查询的补值不改变顺序和界面位置。
- 在同机同份实盘索引上对照当前版本，测量初次汇总和排序的耗时、长期及峰值内存、增量合计和目录顺序的发布延迟，以及普通搜索和大小排序的端到端 P95／P99。覆盖后台首次汇总、稳态和持续 USN 更新，并测试大目录与大量匹配目录。以多轮基准的波动检验普通搜索有无可复现的延迟回退。
- 验证现有 HTTP、CLI 文件大小筛选继续符合原契约。开发测试只运行直接受影响的用例，随包手册说明目录统计口径和排序等待状态。
