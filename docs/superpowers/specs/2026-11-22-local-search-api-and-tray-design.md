# 本机搜索接口、CLI 与托盘运行

启动行为和首版查询范围已确认。

## 托盘运行

手动启动时显示搜索窗口，并创建托盘图标。点击窗口关闭按钮或按 Alt+F4 后隐藏窗口，后台继续采集并更新实时索引，HTTP 和 CLI 继续可用。左键点击托盘图标或右键选择「打开」会恢复原窗口和搜索状态。再次启动同一便携版时，打开已有窗口并复用后端。

从托盘右键选择「退出」才正常结束程序。退出时停止接收查询，沿用现有的采集停止、快照保存和进度提示流程，并遵守「退出时不保存索引」设置。保存异常通过窗口显示。

## 本机 HTTP 接口

桌面程序启动后，普通权限的 .NET 后端默认在 `127.0.0.1:18791` 提供 HTTP/JSON，首版免鉴权。监听范围为本机回环，端口可通过 `NTFS_SEARCH_PORT` 覆盖。端口占用时，桌面可以正常搜索，并提示接口启动失败的原因。

- `GET /v1/status` 返回索引条目数、可查询卷数和卷准备状态。
- `POST /v1/search` 接受查询文本、名称或路径匹配模式、创建时间范围、修改时间范围、文件大小范围、排序、偏移和页大小。返回筛选后的精确总数、索引就绪状态和当前页。行包含名称、完整路径、目录标志、字节大小和 UTC 创建及修改时间，缺失的元数据返回 `null`。

桌面和 HTTP 请求共用当前已经发布的内存索引。索引逐卷就绪时即可返回已发布卷的结果，并在响应中标明覆盖情况。查询限制页大小与并发，超时或请求取消时终止对应的查询。磁盘采集沿用现有进程和启动流程。

## 元数据筛选

修改时间、创建时间和文件大小统一从内存索引筛选。时间范围采用包含起点、排除终点的语义，API 接受带时区的 ISO 8601 时间戳。大小使用逻辑字节数，上下限均包含。各条件取交集，查询文本可以为空。筛选某字段时，缺少该字段的条目不匹配。目录不参与文件大小筛选。

初扫、USN 增量与原生读取回退路径从 NTFS 文件元数据取得创建时间。退出快照保存创建时间及对应的 USN 水位。旧退出快照缺少这一字段，升级后由原有逐卷采集流程补齐一次，之后正常通过快照恢复。

## CLI

`NtfsSearch.Cli.exe search <query>` 和 `NtfsSearch.Cli.exe status` 访问同一个 HTTP 接口并输出 JSON。后端不可达时返回明确错误和非零退出码。`search` 全程作为客户端运行，静态快照查询改用 `search-snapshot`，显式扫描与基准命令继续用于诊断。

`search` 支持 `--created-from`、`--created-before`、`--modified-from`、`--modified-before`、`--min-size-bytes` 和 `--max-size-bytes`，与 HTTP 使用同样的筛选语义。只有元数据条件时可省略查询文本。

## 验收

- 使用隔离的演示索引比较 HTTP、CLI 和桌面查询的结果、计数与排序，并验证后端离线时 CLI 的表现。验证 HTTP 和 CLI 使用同样的元数据边界、缺失值语义与组合筛选后的计数。
- 在 Windows 验证隐藏后托盘可恢复窗口、HTTP 与 CLI 仍然可查、再次启动复用原后端。
- 验证托盘退出正常完成快照流程，且「退出时不保存索引」设置仍然生效。更新随包手册中的托盘、HTTP 与 CLI 用法。
