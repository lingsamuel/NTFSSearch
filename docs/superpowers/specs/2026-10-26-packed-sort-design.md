# 预建排序的24位内存排列

保留名称、路径、大小、修改时间四列预建排列及原比较器，不用按需全量排序换内存。每个卷的行数在1024至16,777,216之间时，将冻结的ID排列存为每项3字节；更小的段和超过24位的卷仍保留int32，不限制总行数或单卷容量。

`SortPermutation`提供只读Count、O(1)下标和实际StorageBytes；不会向调用方暴露底层数组或非托管Span。packed终态用现有IndexArrays.Persistent分配，并额外保留一个zeroed尾字节。下标先检查逻辑位置，再从受GC追踪的托管ref进行4字节未对齐读取并保留低24位，最后一项也位于实际分配范围内。int32回退由内部调用方明确转移数组所有权。

构建继续使用现有Array.Sort/SortIndex.Sort和比较逻辑。可压缩卷仅临时持有普通int order及原scratch，四列复用；每列完成后冻结到最终packed存储。不能将这些临时巨型int数组放入POH。WithView和无已知大小/日期的Path alias仍共享同一SortPermutation对象；目录修正继续保留原有小型int数组和两路归并。

磁盘NTSIDX04及旧NTSIDX01–03格式不变，排序仍是int32。保存仅使用一个最多65536项的普通int块，对有效排列流式解码后写入；修正视图也流式归并，不再一次物化四份全卷数组。只有未修正的同一排列引用可以写alias。加载逐块读取原始int32，先执行range/seen检查再编码，避免越界ID截断成合法24位值；保留已知元数据边界、别名及最终单调性校验。V1无存储排序仍沿用原构建路径。

固定34,408,942行、各卷均小于24位上限时，四列理论净省约131MiB，实际统计包含每份packed的尾字节并去重alias。不能将int32回退谎报为3字节。最终还须以同输入Windows独立进程比较实际活对象、Private、WS、空查询及大命中查询，加载和事后校验不算入查询延迟；不得修改用户Data或进程。
