# 后台刷新计时与目录更新内存放大修复

## 目标与已知证据

用户报告未操作时查询耗时持续变化、内存达到7G。0.4.0将catalog.Changed直接接入用户SearchAsync，重置页码、取消在途查询、覆盖计时和列表选择。Windows实际前台PID113368采样工作集约8.1GiB、私有9.6GiB，后台采集仅128MiB。无暂停System.Runtime采样显示分配峰值约312–446MB/秒；10秒样本的分配中位数约48MiB/秒、范围约21–426MiB/秒，GC暂停峰值约0.4秒/秒。

九卷34,411,699行的只读统计：UTF16名称约1595.7MiB，32字节记录1050.2MiB，四列排序525.1MiB，身份数组298.3MiB，完整目录路径约814MiB、目录引用表35.8MiB，基线约4319MiB。实时目录图额外占用；D卷实际图增加约264MiB。当前结构本体已超过Everything约3197MiB私有内存，不能靠强制GC宣称达标。

## 查询刷新

复用现有SearchCatalog/SearchAsync，区分用户请求与后台更新。用户输入、排序、条件、翻页的成功结果才更新“用户查询耗时”；后台更新继续显示精确计数和实时结果，保持上一用户计时。后台通知合并，最多一个执行中的查询和一个待刷新标记，不因后台事件取消用户查询或丢弃刚完成的不可变快照结果。以用户请求代次阻止旧输入回写，完成后再追赶最新索引。

后台更新不重置页码；仅当前页因删除越界时夹到最后有效页。相同首屏不替换ItemsSource；实际变化保持仍存在的选中路径和滚动位置。关闭和取消仍释放查询资源。不要关闭实时更新、隐藏真实耗时或以当前页没有某卷误判变化无关。

UI线程上的独立请求状态负责用户代次、成功用户耗时和唯一待刷新标记；单任务泵串行调用现有搜索。后台首次通知开启200ms合并窗口，后续通知不延期；窗口到期时有查询在运行则只保留一次后继刷新。初次自动加载尚无成功用户查询时不伪造用户计时。结果集合保持绑定，逐行复用、移动或替换实际变化的显示对象；层内Id改变不视为显示变化。

## 内存修复边界

首先消除现有实现的重复路径分配：目录图无变化不重算路径，目录新增不影响现有子树；改名/移动/删除按旧目录图的祖先身份筛选各层父目录引用（两遍MFT采集和旧检查点可能存在任意深度的图/路径文本不一致，不能仅使用字符串前缀），祖先缓存固定上限4096并复用工作区，仅处理受影响目录及后代，并复用已有路径字符串和未变的共享数组。原始基线、完整FRN代际、硬链接、删除隐藏和四列排序的正确性保持现有协议。不得引入全卷逐文件对象字典、定时GC或扩大内存验收预算。

已量化微小增量段的NameArena首块固定分配2MiB；首块按IndexBuilder已有规模自适应，在保持ChunkChars逻辑偏移、非末块完整长度和现有快照格式的前提下增长，避免每个小文件更新制造巨型垃圾。大基线仍直接使用完整块。

检查点读取保持旧格式兼容，内容相同的目录路径和名称应复用已有对象，避免读完巨量字符串才发现没有变化。保存后只提取增量段ID时，直接校验并跳过目录文本，不创建两轮完整目录字符串。此轮不换索引存储格式、不要求用户重新扫描、不全面改写名称/路径压缩布局。基线4319MiB超过Everything的问题如未实测解决，必须在结果中保留，不能将分配量下降等价于内存达标。

## 验证

UI请求合并、后台不改用户计时/页/选择、持续变化不饿死结果、用户新输入抢占和关闭取消回归。核心验证新增无关目录、目录树移动/删除、硬链接/代际复用、全部排序和检查点恢复，使用有意义的大目录样本测分配：无关目录新增不能按整卷路径字符总量分配，移动成本随受影响子树增长。Windows以隔离测试数据复用真实索引，记录修复前后同场景工作集、私有内存、托管活内存、分配速率和暂停；不停止或注入用户正在运行的进程，不修改Everything库，不向生产卷注入大规模文件变动。
