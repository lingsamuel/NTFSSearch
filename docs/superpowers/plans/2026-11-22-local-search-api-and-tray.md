# 本机搜索接口、元数据筛选与托盘实施计划

**目标** 让 Windows 和 WSL 服务通过 HTTP 和 CLI 查询桌面后端维护的同一份索引，并能按创建时间、修改时间和大小筛选。

**架构** 现有 .NET 后端继续拥有实时索引，HTTP 和桌面从同一个 `SearchCatalog` 读取，CLI 通过 HTTP 取结果。Tauri 在托盘保留原窗口和后端，只有托盘退出时结束采集并保存快照。

## 创建时间采集与存储

- 先扩展索引、退出快照和增量测试，用不同的修改时间和创建时间核对新增及更新后的行，确认现有代码缺少创建字段。
- 让 `MftMetadata`、`RawMftState` 和 `NativeFileState` 从现有元数据读取创建时间，跟随现有初扫与 USN 数据传输。给 `SearchRow` 和构建器增加可空 `CreatedUtcTicks`，使用单一内存表示供查询、合并及持久化读取。
- 更新退出快照版本并验证旧版快照触发一次常规卷采集。保留静态快照与旧诊断数据的读取兼容性。验证采集消息、USN 增量和快照恢复中的时间值。

## 核心查询和客户端

- 先在 `SearchTests.cs` 验证多个卷及增量层内的数量、排序、分页、缺失值和时间边界。核心使用 `SearchFilter` 传递所需比较范围，`SearchCatalog` 将筛选传入原有 `SearchIndex.Prepare`，匹配位图负责同一快照下的计数与分页。
- 先用隔离演示后端验证 HTTP 和 CLI 搜索及离线退出码。后端在回环地址提供 `GET /v1/status` 与 `POST /v1/search`，传递请求取消且限制页大小和并发。CLI 将同一字段映射成选项，输出 JSON，静态查询通过 `search-snapshot` 进入。

## 托盘和便携版

- 扩展 Windows 窗口验证，先检查关窗后后端仍在运行，再通过托盘打开和退出。Tauri 复用原窗口，实现同一安装目录的单实例，托盘退出调用现有的退出保存握手。
- 更新 README 和随包手册，同步各入口的版本号。开发时只运行受影响的测试。使用 `scripts/build-windows.ps1` 构建并用隔离便携版验证托盘、端口接口、CLI 和快照，核对版本后交付。
