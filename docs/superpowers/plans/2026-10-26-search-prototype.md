# NTFS 搜索原型实施计划

> 执行方式：当前会话顺序实施，复用已审查的系统接口和 .NET 能力。用户已要求试着实现，无需再次确认相同设计。

**目标：** 交付可以运行的 Windows 原型，并以实际容量测试检验索引布局与查询，而不是承诺未经验证的性能。

**架构：** .NET 核心库维护连续名称区、32 字节记录、共享父路径和独立排序排列；CLI 复用同一核心完成导入、搜索与基准；WPF 通过后台任务调用核心。NTFS 枚举使用 Win32 接口，快照采用校验与同卷替换。原型尚不承担生产后台服务和实时 USN 回放的交付承诺。

**技术栈：** .NET 10、C#、WPF、xUnit。已阅读 everyfind 的索引布局、路径与 NTFS 枚举实现；其 lossy UTF-16、全量 FRN 哈希表及名称区 32 位偏移不适合直接作为本项目亿级核心，保留原生 UTF-16 与 64 位名称偏移。

## 任务 1：工程和行为测试

- [x] 建立 `src/NtfsSearch.Core`、`src/NtfsSearch.Cli`、`src/NtfsSearch.App`、`tests/NtfsSearch.Tests`。
- [x] 测试覆盖空格 AND、引号、跨目录边界、大小写与 Unicode、四列双向排序、未知元数据、稳定分页、取消。
- [x] 执行 `dotnet test tests/NtfsSearch.Tests -c Release`，先看到缺少核心行为的失败，再实现。

## 任务 2：紧凑索引和查询

- [x] `NameArena.cs` 使用分段 UTF-16 名称区；`IndexBuilder.cs` 保存共享父路径；`SearchIndex.cs` 冻结后只读。
- [x] `SearchQuery.cs` 统一解析；`SearchEngine.cs` 并行计算全量匹配位图与精确计数，只对结果页构造字符串。
- [x] `SortIndex.cs` 维护四列 ID 排列；少量命中直接排序，大量命中使用位图筛选预建排列。
- [x] 执行行为测试，确认结果与独立 LINQ 真值一致。

## 任务 3：输入与持久化

- [x] `EfuImporter.cs` 流式读取 EFU CSV，不借助 Everything 执行查询。
- [x] `SnapshotStore.cs` 流式保存、SHA-256 校验、临时文件刷新后替换，保留上一代；校验失败给出明确错误。
- [x] `NtfsEnumerator.cs` 只读调用 `FSCTL_ENUM_USN_DATA`；严格检查变长记录和版本，不将 USN 时间误作文件修改时间。原型明确标记未补全的大小、时间与硬链接。
- [x] 测试 CSV 引号和换行、快照往返及损坏、USN 缓冲区越界与未知版本。

## 任务 4：CLI、桌面和规模验证

- [x] WPF 提供查询、完整路径模式、排序、取消、导入和加载快照；任务完成前保持可响应，旧任务不能覆盖新结果。
