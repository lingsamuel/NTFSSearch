# 索引内存设置实现计划

> 按已确认的设计实施。分别验证索引布局、快照恢复、排序生命周期和设置界面，再做端到端验收。

**目标** 在设置中提供四个下次重启生效的开关。预计算排序、修改时间、文件大小默认开启，创建时间默认关闭。

**实现方式** 用字段标志控制建立、恢复及更新索引。可选元数据放入独立列。退出快照分卷标记元数据覆盖范围。按需排序复用现有排列和比较逻辑。设置只在后端启动时确定索引能力。

## 1. 索引字段与恢复

- [x] 用真实索引测试禁用元数据、跨层更新与合并，确认禁用字段无持久数组且全范围字段值可读。
- [x] 改造 `IndexRecord`、`IndexBuilder`、`SearchIndex` 和各元数据访问者。保留 `SnapshotStore` 的旧文件布局和校验。
- [x] 用退出快照测试覆盖旧格式投影、元数据覆盖范围、部分卷需要补采及回放。
- [x] 在 `ExitSnapshotStore`、`SearchHost` 和 `MemoryVolumeBackend` 的实际装载和采集入口应用配置。

## 2. 按需排序

- [x] 用匹配、分页和更新用例覆盖预计算与按需两种策略的等价性，检查切列后旧排列可以释放。
- [x] 让 `SearchIndex` 按需构建可复用排列，`SearchCatalog` 为桌面选中列管理缓存。外部查询使用请求期间的排列。
- [x] 目录大小合计独立于大小排序排列，在需要排序时构建并随当前列释放。

## 3. 设置与交付

- [x] 复用设置页统一保存。设置页显示重启规则、待重启状态及关闭文件大小的具体影响。桌面根据本次启动能力显示列和空间分析入口。
- [x] 验证设置保存后当前进程的能力、重启后的列和空间分析，以及 HTTP 和 CLI 对禁用字段的处理。
- [x] 更新 README 和随包手册，运行相关测试和 Windows 便携版构建。以同一份快照核对字段成本和全量切列延迟。
