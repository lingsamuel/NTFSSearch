# 多盘并行读取

用户要求不同盘的索引一起读取。本轮同时修正管理员采集宿主的串行扫描，以及普通窗口的串行缓存加载，继续复用原查询、快照和子进程实现。

## 约束

- 不同物理盘可并行扫描，同一物理盘的多个卷共享一个扫描名额；跨盘卷占用其所有物理盘。未知拓扑保守归组。
- 扫描最多4个子进程，缓存加载最多3个任务；按CPU数量下调，并为前台查询保留CPU。扫描进程低优先级且限制各自 .NET 处理器数。
- 扫描使用系统可用内存的一半作为调度估算预算，结合已有快照和MFT规模估计任务开销。估算只用于调度，不是性能验收或硬内存保证；超过预算的大卷仍允许单独运行，避免永远排队。
- 调度循环不等待某一卷完成，持续发现磁盘与刷新请求；任务完成即释放资源并加入下一卷。
- 同卷去重；运行期间多次刷新合并为最多一次后续任务。卷离线取消任务，但其占用要等实际退出才释放。
- 缓存完成即发布到搜索，不等待所有卷；异常隔离、取消、旧版本保护与损坏回退保持原约定。

## 实施和验证

1. 写并发、物理盘冲突、内存预算、失败隔离、刷新去重和并行加载的失败测试。
2. 实现可测试的卷任务调度器与资源策略，复用Win32卷句柄/控制接口发现物理盘与MFT规模。
3. 接入现有采集宿主与缓存加载器，记录并发峰值，更新0.3.0。
4. 单元测试、Windows磁盘拓扑与无窗口真实并行读取验证，审查后提交与打包。

## 验证结果

42项测试通过；9个卷设备编号与Windows Get-Partition结果一致。真实隔离缓存流程观察到4个采集子进程重叠，E盘1,614,524条真实记录先完成可查，G盘补位，完成进程报告6个逻辑处理器。验证首卷与并发后主动停止；最终发布包另外进行Windows无窗口自检。见docs/benchmarks/concurrent-volumes-0.3.0。
