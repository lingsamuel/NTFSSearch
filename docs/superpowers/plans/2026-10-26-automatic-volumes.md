# 自动发现和采集 NTFS 磁盘

用户明确要求启动后自己发现硬盘并读取，不能要求提供索引。此前默认演示数据和导入入口偏离该需求，本轮直接修正，不再请求重复确认。

## 行为约定

- 正常启动立即发现所有已就绪的本地固定/可移动 NTFS 卷，不索引网络共享、非 NTFS 卷或无盘符恢复分区。
- 默认界面不加载演示数据，不要求选择索引或输入盘符。
- 缓存按卷 GUID 与挂载盘符区分，自动加载；重新格式化、盘符复用和盘符改变不能串库。
- 普通权限窗口自动启动独立的管理员采集进程，使用 Windows UAC；一次授权处理所有卷，无管理员终端步骤，不借用 Everything 的服务。
- 后台逐卷扫描、保存并发布；每个已完成卷立即可查。单卷失败不能阻断其余卷，取消和窗口关闭必须停止本次采集。
- 快照与发布清单分开提交，保留上一代并自动回退；损坏不反复载入，不要求用户删库。
- 定期发现新插入和离线磁盘；挂载身份变化时更新可查询卷集合。
- 多卷查询的精确总数与全局四列排序、分页必须正确，复用原有查询引擎。
- 文件级实时 USN 回放仍需后续实现，本轮不以反复全卷扫描冒充实时更新，也不改变既有亿级性能标准。

## 顺序实施

1. 先写多卷全局排序/计数、自动发现加载、缓存回退与卷身份测试，确认失败。
2. 实现卷发现、自动缓存和搜索目录；原有 SearchIndex 与 SnapshotStore 保持复用。
3. 实现独立采集宿主、自动提权启动、逐卷状态与父进程生命周期约束。
4. 修改 WPF 默认启动和工具栏，增加每卷进度与重新扫描入口。
5. Windows 真实卷发现、无窗口默认流程自检、权限与缓存集成验证；更新文档、版本 0.2.0、发布包并独立提交。

## 实施与验证结果

上述5步已完成。31项自动化测试、Windows发布版无窗口自检通过。9个NTFS卷的实际首批MFT读取均成功；真实自动流程已完成C盘7,527,764条目录项的采集、快照发布、自动加载和查询，验证首卷后主动停止。详见docs/benchmarks/automatic-volumes-0.2.0。文件级实时USN和元数据补全不属于本轮已完成范围。
