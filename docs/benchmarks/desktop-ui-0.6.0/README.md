# 0.6.0 Windows 桌面验收

Windows x64 便携包解压后，原有 `NtfsSearch.App.exe --smoke-test` 入口及新窗口自检均通过。核心测试通过 212 项。Windows 窗口自检覆盖启动焦点、精确计数、翻页、大小双向排序、路径匹配切换、键盘选择、右键菜单、打开失败反馈、660×420 布局和关闭后端。

将旧版生成的 V4 静态缓存放入隔离的旧发布目录，执行正式构建脚本升级。缓存 SHA-256 一致，旧 WPF 文件和开发文档已移出发布目录。用正常桌面入口发现本机九个 NTFS 卷，并读取实验卷清单下的 1,000 条模拟记录。此项使用独占的实验采集锁，真实 UAC 扫描和九盘增量回放沿用既有诊断验收入口。

## 同机对照

旧版 WPF 和新版便携包各加载 `DemoData.Create(1_000_000)`，默认路径匹配与名称升序。每条查询执行三次，表中为中位数。核心耗时取 `SearchCatalog`，窗口耗时从输入变更开始，WPF 取 Dispatcher 空闲时刻，Tauri 取更新结果后的绘制帧。两项窗口采样使用各自的 UI 调度机制。

| 查询 | 精确匹配 | WPF 核心 ms | Tauri 核心 ms | WPF 窗口 ms | Tauri 窗口 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| `"hello world"` | 58,824 | 2.25 | 2.05 | 41.58 | 28.40 |
| `目录009` | 100 | 11.90 | 8.78 | 70.23 | 26.70 |
| `ntfs-absent-fixture` | 0 | 2.13 | 2.22 | 30.69 | 9.60 |

加载后等待两秒采样。WPF 私有内存约 396.6 MiB，Tauri、WebView2 和 .NET 后端整棵进程树约 625.6 MiB。进程树工作集分别约 366.0 MiB 和 650.5 MiB，求和包含各进程报告的共享页。样本使用固定合成输入，真实多盘常驻占用和负载仍需要单独测量。原始采样见 [WPF](wpf-0.5.0.json) 和 [Tauri](tauri-0.6.0.json)。
