## 测量口径与限制

- 名称唯一、ASCII 为主，平均约17个UTF-16字符，少量含空格短语；每1000个文件共享一个父路径。没有真实元数据的长尾分布。
- 名称、路径、大小、修改时间4个排序排列都已构建。数值包含静态文件大小与修改时间，但没有实时更新映射、服务进程或GUI本体。
- 每项计时包含全量精确计数与全局排序后的100条结果，不含界面绘制。没有搜索结果缓存。
- 大规模每组仅3次热查询；记录原始样本与中位数，不报告P95/P99。
- 内存为进程观测值，不是构建峰值；不能用结构体估算代替进程占用。
- 有序数据在建排序时可直接验证已有顺序，构建时间显著偏乐观。1亿打乱输入尚未测试。
- 打乱3500万的初始串行排序曾在约200秒时停止；改为有界并行排序和优先队列归并后完成约61秒。
- 归并缓冲复用使同一打乱数据构建后的私有提交观测从约3.255 GiB降至约2.859 GiB；这属于已测数据下的实现改进，不是生产内存承诺。
- 真实NTFS大小、时间和硬链接补全、USN一致性、增量更新、冷启动仍未完成；管理员全卷扫描未验证。

## 正确性与平台检查

- 19项自动化测试通过，包含跨路径边界、原始UTF-16、校验损坏、未知元数据和并行排序取消。
- 独立审查使用朴素真值核对了528组查询、4列双向排序和不同分页偏移，覆盖稀疏与大量结果分支。
- Windows发布版本的WPF自检通过，未显示窗口或模拟键鼠；CLI快照创建和查询通过。
- 真实Win32调用验证了普通权限下明确拒绝卷读取且不创建输出文件；这不能证明管理员全卷枚举正确。

## 后续优先项

先用代表性真实元数据检验分布与资源成本，改进全表扫描和相同条件下切换排序的复用；再接入可靠USN回放、完整元数据与服务隔离。每项继续以同机同等条件对标，不放宽性能要求。
