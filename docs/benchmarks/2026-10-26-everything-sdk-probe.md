# Everything 只读 SDK 探测

日期：2026-10-26。

## 目的与限制

确认本机实际配置，探索可重复测量的方法。此次数据不是 GUI 交互延迟基准，不能据此否定用户报告的即时体验，也不能用它为替代软件制定更宽松的验收线。

使用官方 Everything SDK 1.4 的 64 位 DLL，从 Windows PowerShell 调用当前 Everything 1.4.1.1009。没有更改 Everything 的数据库、设置、索引字段或窗口内容。

## 方法

- 数据库已加载；名称、路径、大小、修改时间均由 SDK 确认支持快速排序。
- 使用 `Everything_SetMatchPath(true)`，与现有完整路径匹配设置一致。
- 使用 `Everything_SetMax(100)` 和请求标志 `0x53`，请求名称、路径、大小、修改时间。
- 计时覆盖同步 `Everything_QueryW(true)`，随后读取精确总数、实际返回数、实际排序方式。请求排序与实际排序逐项核对。
- 查询匹配范围未限制为 100 条：限制的是传输行数，精确总数仍覆盖全部匹配记录。
- 各组连续测量 3 次。样本量不足以报告 P95/P99，且连续同查询存在缓存偏差。
- 当前精确对象数：34,381,169；对象数量可能随文件系统变化。
- 不计入键盘输入、GUI 查询复用、GUI 绘制和用户交互，也未隔离当时的后台负载。SDK 和 GUI 是否走相同查询复用路径尚未验证。

## 结论边界

已验证读取配置和通过 SDK 获取精确匹配数及指定排序的可行性。观测到的 SDK 延迟明显高于用户描述的界面体验，原因尚未定位；后续需要区分 IPC、独立查询、增量输入复用、完整路径匹配与 GUI 绘制。

此次不能形成替代软件的速度验收线。也没有对 1 亿对象、替代引擎内存、批量更新或稳定性作出测试结论。
