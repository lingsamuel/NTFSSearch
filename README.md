# NTFS Search

Windows NTFS 文件搜索工具，版本 0.6.1。桌面界面使用 Tauri 和 Vue，.NET 负责索引和搜索。

## 使用

Windows 便携版解压后双击「启动搜索.cmd」。启动、搜索、索引状态和升级步骤见[使用说明](manual/README.md)。

## 搜索

- 默认匹配完整路径，可切换为仅匹配名称。
- `hello world`：两个条件都满足，允许不相邻。
- `"hello world"`：包含空格的连续文本。
- 带反斜杠的条件按路径匹配，支持跨父路径与文件名边界。
- 多卷结果按同一排序规则归并，显示精确总数；每页仅构造200条结果。
- “用户查询”耗时只在输入、排序、条件或翻页请求完成后更新。后台索引变化继续刷新结果和数量，但合并刷新请求，并保持用户耗时、当前页、仍存在的选中项和滚动位置。
- 打开文件与所在目录、复制路径均使用当前桌面用户权限。

支持名称、路径、文件大小和修改时间排序；大小和时间从真实 NTFS 元数据读取，增量更新也保持相同语义。USN 事件时间不会冒充文件修改时间。

## 多盘并行

不同物理盘同时采集，当前32逻辑处理器主机最多4个采集子进程、3个缓存加载任务。完成一个任务就补下一个，某卷很慢时其他卷完成后立即可查。界面显示正在并行的卷数。

同一物理盘的多个分区不会同时扫描；跨盘卷预留所有相关设备，未知拓扑保守独占。扫描进程降低优先级并限制各自的 .NET 处理器数，缓存加载与前台搜索独立推进。

调度结合可用内存、MFT规模和已有快照估算任务开销，内存紧张时暂停接纳新扫描。估算仅用于调度；常驻资源与搜索延迟仍按同机同数据的 Everything 基线验收。超预算单卷可单独运行，避免永远排队。

更新时先关闭旧版窗口再启动新版，以便后台采集宿主也更新。

## 自动采集与缓存

- 使用卷 GUID 与挂载路径共同标识缓存，避免盘符复用、重新格式化或挂载变更串库。
- 每卷使用独立采集子进程；普通搜索窗口只负责加载和查询。取消、父进程退出和超时会停止采集任务。
- MFT 枚举保留原始 UTF-16 和完整文件引用。父目录缺失时通过 `OpenFileById` 补查；不可达或循环记录单独统计，不再使整盘失败。
- 快照 SHA-256 校验后加载；排序排列一并持久化，启动时验证并恢复，避免重新排序整个卷。
- 快照完成后才原子发布清单，保留上一代。主文件损坏时优先读取同代健康备份；仅需跨代回退或日志无法补齐时请求后台重建，同一损坏版本不会每两秒反复加载。
- 同卷发布使用跨进程互斥；读取允许原子替换，避免 Windows 文件共享冲突。卷进度和已完成记录数直接显示在窗口中。
- 默认数据目录为程序旁的 `Data`，前台与管理员采集进程使用同一绝对路径。移动软件时一并移动 `Data` 即可；需要可写的程序目录，不会静默退回全局目录。
- 首次升级自动复制旧版 `%LOCALAPPDATA%\NtfsSearch\Volumes` 的静态缓存并校验，已有有效目标优先，旧副本保留以便恢复。旧格式缺少文件身份和 USN 水位，因此升级时各卷只重建一次；之后正常启动只接续增量。
- 硬链接按每个文件名及父目录记录；完整文件引用包含代际，避免记录槽复用误认旧文件。扫描期间持续捕获 USN，发布前回放变化。
- 文件新增、删除、改名、目录移动和硬链接增删通过 USN 更新，界面对象数与搜索结果随提交变化；监控不占用初次扫描的并发名额。
- 增量事务先可靠提交再推进游标。查询使用只读基线、隐藏位图和增量段，周期保存检查点并回收已消费日志；普通变化不复制或重新排序整卷。
- 仅日志换代、截断、损坏或显式重新扫描时重建受影响卷；其他卷继续提供结果。`Data` 内部文件不纳入索引，避免自身日志触发无限反馈。

0.5.0可直接读取0.4.0/0.4.1的V3数据库、旧检查点及增量日志，不因布局升级重扫MFT。旧快照在恢复查询后逐卷后台转为V4，原子替换并保留健康备份；取消或失败继续使用已有索引。V1/V2仍可读取，但缺少身份和USN信息的旧静态库仍需按既有规则重建一次。

## 内存与排序

名称精确去重，可逆压缩适用的ASCII文件名；其余保留原始UTF-16，显示大小写不变。记录由32字节压缩至20字节，大文件大小另存完整64位值；目录身份图复用基线名称与记录，仅为变化保留覆盖。大型长期数组采用独立分配区域，减少加载后碎片，不强制GC或修剪进程工作集。

四列排序只缓存行号排列，不复制四份文件数据。适用卷的行号由4字节压至3字节，超过范围自动使用4字节，不限制单卷容量。固定3441万对象的四列排列由525MiB降至394MiB。没有采用切换时全量重算：同机九卷实测重建一列需要2.12至7.01秒，舍弃其他三列只能省约394MiB，无法保留近瞬间切换。

## 当前边界

这是持续开发中的实现。0.4.1实际界面约3441万对象，私有内存5.35GiB；0.5.0相同九卷约3443万对象的最终界面自然私有内存约3.38GiB，重启无全卷扫描；详细测量见`docs/benchmarks/compact-memory-0.5.0`。完整记录区分自然进程占用、诊断GC后活对象、静态查询与实时界面，不能相互替代。硬链接补全后，与当前Everything库的剩余数量差仍在逐文件核对，不能以总数接近宣布完全一致。部分查询仍需遍历数千万行，尚未达到Everything的全部即时体验；初次完整索引、大规模变化与亿级容量仍需同机验收。

持久化采用V4快照、带提交边界与校验和的增量日志、查询视图检查点。异常退出后从最后完整事务恢复；卷上的USN已被系统回收且本地捕获也无法补齐时，只重建该卷。旧版0.4.x不能读取新版V4/新检查点；如需回退版本，应在升级前保留整份Data备份，不能混用新旧检查点及日志。

## 开发与验证

```sh
dotnet test NtfsSearch.slnx -c Release
dotnet run --project src/NtfsSearch.Cli -c Release -- drives
dotnet run --project src/NtfsSearch.Cli -c Release -- bench 1000000 report.json shuffled 5
```

在 Windows 安装 Node.js、Rust MSVC、Microsoft C++ Build Tools 和 .NET 10 SDK，使用 PowerShell 执行 `scripts/build-windows.ps1` 构建便携发布目录。Windows 使用 WebView2 Runtime 渲染，核心测试也可在 Linux 运行。

诊断参数可传给 `app/NtfsSearch.App.exe` 或 `app/NtfsSearch.Backend.exe`。`--smoke-test report.txt` 执行后端自动流程自检；`--probe-volumes report.json` 每卷少量 MFT 采样并核对元数据与 USN 状态；`--automatic-test report.json` 运行正常自动采集链路，首卷真实结果可查询后停止；`--parallel-test report.json` 使用隔离缓存验证实际多盘重叠读取，首卷可查且观察到至少两个采集进程后停止；`--verify-live report.json` 在专用测试目录验证实际硬链接、目录移动、检查点与停机回放；`--full-audit report.json` 使用报告旁的隔离 `Data` 等待全部卷进入增量模式，并记录本次启动的扫描卷，供重启免重扫验收。

便携版构建后，可运行 `node tests/desktop-window.mjs artifacts/windows/app/NtfsSearch.App.exe artifacts/desktop-window`，在 Windows 窗口中验证搜索交互和退出。该自检使用独立的演示索引。

命令行保留 EFU 导入、快照查询和显式扫描作为开发诊断能力，不属于桌面正常使用步骤。0.1.0容量数据和当前验证记录见 `docs/benchmarks`。

参考：[微软 MFT 枚举](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_enum_usn_data)、[按文件ID打开](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-openfilebyid)、[USN V2格式](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-usn_record_v2)。此前阅读 everyfind 作为参考，本项目不依赖该程序运行。NTFS 数据流读取复用 DiscUtils，依赖与许可见 `docs/native-dependencies.md`。
